# 筋トレノート

自宅のインクラインベンチと可変式ダンベルで行う筋トレを記録する PWA（Web アプリ）。

iPhone のホーム画面に追加して、ネイティブアプリのように使う。
データは端末内にのみ保存され、サーバーへは送信しない。

## 特徴

- **所有しているダンベルの段階だけを選べる** — ＋ / − ボタンが実際に設定できる15段階の間を移動する
- **前回の記録が常に見える** — 種目を選ぶ段階で「前回 11.5kg（7/31）」が出る
- **上げるか据え置くかを自動で判断** — 目標回数を全セットで達成したら、次回は1段階上の重量を提案する（ダブルプログレッション）
- **筋の構造に応じた回数レンジ** — 平行筋は 10〜15回、羽状筋は 8〜12回 を既定にする（種目ごとに変更可）
- **部位ごとの休憩時間** — 脚180秒〜腕90秒を既定にし、直前に行った種目の設定でタイマーが動く
- **休憩はセットごとに調整できる** — ウォームアップに切り替えると自動で1分に縮む。± 15秒でその場から変えられる
- **種目カルテ** — 種目ごとの推奨重量・自己ベスト・実施履歴・重量の推移をまとめて確認できる
- **種目を自由に追加** — 部位と名前を入れるだけ。回数レンジと休憩時間は部位から自動で決まり、作った種目は以後ずっと選べる
- **フォームの参考リンク** — 記録画面から1タップで YouTube 等へ。未設定の種目は種目名で自動検索する
- **休憩時間を自動計測し、終了を音で知らせる** — 休憩中だけ画面を点けたままにして確実に鳴らす。鳴らす長さは1〜12秒から選べる（設定でオフ可）
- **メニュー登録** — 「胸の日」などを登録して一括で呼び出す
- **記録し忘れた日を後から入力** — 履歴のカレンダーから日付を選べば、過去の日も同じ操作で記録できる
- **バックアップは保存先を覚える** — 対応ブラウザなら2回目以降はボタン1回で同じファイルに上書きされる
- **食事の記録と栄養計算** — 日本食品標準成分表の2,538品を同梱。食材を選んで量を入れるとエネルギーとPFCを積算する
- **マイ食品** — 成分表に無い市販品やプロテインは、パッケージの表示どおり「1食30g当たり」で登録できる
- **市販品のオンライン検索** — プロテインやサラダチキンは Open Food Facts から取り込める。取り込むとマイ食品として残り、次からは通信不要
- **業務スーパーの商品を同梱（169品）** — 「業務スーパー」と入力すれば一覧になり、圏外でも選べる
- **日常語で引ける食品ショートカット（166品）** — 「白米」で「ごはん（白米・炊いた）」が先頭に出て、「茶碗1杯 180g」から量を入れられる
- **個数で入れられる食品** — 梅干し・卵・バナナのように数える方が早いものは「3個」と入れられる。g との切り替えも1タップ
- **量は前回のぶんから始まる** — 毎朝20g飲むプロテインを、毎回100gから打ち直さずに済む
- **外食を料理名で記録（50品）** — 「牛丼」「ラーメン」「カツ丼」で1食分のカロリーとPFCが入る。食材ごとの量が分からなくても記録できる
- **調理済み食品に1皿の分量** — 成分表の炒飯・ぎょうざ・から揚げ等48品を、日常語と1皿分量で引けるようにした
- **成分表に無い調理法の見積もり** — 鶏むね肉の「ゆで」は成分表に無いため、ささみの生→ゆでの変化から見積もった値を用意（見積もりであることは画面に明記）
- **調理違いは畳んで表示** — ブロッコリーの5件が「生」1件＋「調理違い3件」になり、選ぶ対象が減る
- **献立テンプレート** — 「いつもの組み合わせ」を登録して、朝食にも夕食にも1タップでまとめて記録。前の日をそのままなぞることもできる
- **運動と食事を切り替える下部タブ** — 左端で系統を入れ替え、設定だけを右端に常設する
- **ランニングの記録** — 距離と時間を入れるとペース・速度・推定消費カロリーが出る（GPS記録は非対応）
- **自重トレーニングの記録** — 動画に沿った腹筋などは、時間と強度（軽め/ふつう/きつい）で消費カロリーを出す
- **体組成の記録** — 体組成計の表示（体重・体脂肪率・筋肉量・内臓脂肪・基礎代謝）を写すと、除脂肪体重まで出す。身長を入れれば BMI も出る
- **過去の体組成も入力できる** — 記録シートの日付を押してカレンダーから選べば、測り忘れた日やアプリを入れる前の記録も残せる
- **消費カロリーの推定** — 筋トレと有酸素をMETsから見積もり、ホーム・履歴の詳細・食事タブに表示。基礎代謝を入れればグラフで摂取と消費を重ねて見られる
- **グラフでの分析** — 「栄養」と「からだ」を切り替え、2週間／1か月／3か月で見比べられる
- **体組成の推移** — 体重（7日移動平均つき）・体脂肪率・除脂肪体重・筋肉量・BMI。期間内の変化量と週あたりのペースも出す
- **エネルギー収支の分析** — 収支を積み上げて「体脂肪◯kg相当」に換算し、同じ期間の実際の体重変化と突き合わせる
- **週あたりの部位別セット数** — 足りていない部位がひと目で分かる（目安は週10〜20セット）
- **バックアップの書き出しと復元** — JSON ファイルとして保存でき、未書き出しならホームで督促する
- **白黒のみの画面** — iOS の外観設定に連動し、ライトでは白背景・黒文字、ダークでは黒背景・白文字になる

## 技術構成

| 領域 | 採用 |
|---|---|
| ビルド | Vite 8 + TypeScript 6 |
| UI | React 19 |
| データ保存 | Dexie（IndexedDB） |
| グラフ | Recharts |
| ルーティング | React Router |
| PWA | vite-plugin-pwa（Workbox） |
| テスト | Vitest（単体）／ Playwright（E2E） |

## 開発

```bash
npm install
npm run dev          # 開発サーバー（http://localhost:5173）
```

| コマンド | 内容 |
|---|---|
| `npm run dev` | 開発サーバーを起動（同一 Wi-Fi の iPhone からもアクセス可） |
| `npm run test` | 単体テストを監視モードで実行 |
| `npm run test:run` | 単体テストを1回実行 |
| `npm run coverage` | カバレッジ付きで実行（しきい値 80%） |
| `npm run e2e` | Playwright で E2E テストを実行 |
| `npm run typecheck` | 型チェック |
| `npm run lint` | 静的解析 |
| `npm run build` | 本番ビルド（`dist/`） |
| `npm run icons` | PWA アイコンを再生成 |

## iPhone にインストールする

### 方法1: 開発中に、同じ Wi-Fi から試す

1. Mac で `npm run dev` を実行する
2. 表示される `Network: http://192.168.x.x:5173/` を iPhone の Safari で開く
3. 共有ボタン → 「ホーム画面に追加」

この方法は Mac が起動していないと開けない。日常利用には方法2を使う。

### 方法2: GitHub Pages に公開して、どこからでも使う（推奨）

方法1は Mac と同じネットワークにいる必要がある。日常利用にはこちらを使う。
**記録したデータは iPhone の中だけに保存され、公開先のサーバーには送られない。**

`main` に push すると GitHub Actions が型チェック・テスト・ビルドを行い、
GitHub Pages へ自動デプロイする（`.github/workflows/deploy.yml`）。

1. 発行された HTTPS の URL を iPhone の Safari で開く
2. 共有ボタン → **「ホーム画面に追加」**
3. ホーム画面のアイコンから起動する（Safari の UI が消え、アプリのように全画面で動く）

**一度ホーム画面に追加すれば、以降はオフラインで起動できる。**
Mac の起動状態やネットワークに依存しない。

#### サブディレクトリ配信への対応

GitHub Pages は `https://<user>.github.io/kintore-note/` のように
サブディレクトリで配信されるため、次の対応を入れてある。

- `VITE_BASE_PATH` でベースパスを切り替え（アセット・マニフェスト・Service Worker）
- `scripts/postbuild.mjs` が `404.html` を生成し、SPA のパス直打ちに対応
- 公開前の確認用に `scripts/smokeBuild.mjs`（実際のベースパスで起動・遷移・アセット取得を検証）

```bash
VITE_BASE_PATH=/kintore-note/ npm run build
VITE_BASE_PATH=/kintore-note/ npx vite preview --port 4173
node scripts/smokeBuild.mjs
```

#### 別のホスティングを使う場合

`public/_redirects` を同梱しているため、Cloudflare Pages / Netlify にも
`dist/` をそのまま置ける（ルート配信ならベースパスの指定は不要）。

## バックアップについて（重要）

記録は **iPhone の中だけ** に保存されている。
端末のストレージが逼迫した場合など、ブラウザがデータを削除する可能性がゼロではない。

**設定 → バックアップを書き出す** を定期的に実行し、
「ファイル」アプリや iCloud Drive に保存しておくことを推奨する。
最後の書き出しから14日経過すると、設定画面に警告が出る。

復元は **設定 → バックアップから復元する** から行う（現在のデータは全て置き換わる）。

## ディレクトリ構成

```
src/
  domain/       純粋なロジックと型（永続化を知らない）
  data/         Dexie スキーマとリポジトリ
  features/     画面（workout / today / history / charts / exercises / templates / settings）
  components/   共通 UI 部品
  hooks/        共通のデータ購読・状態
e2e/            Playwright の E2E テスト
docs/           要件とデータモデルの設計
scripts/        アイコン生成・スクリーンショット取得
```

[docs/data-model.md](docs/data-model.md) を参照。

## 制約

- **休憩終了の音は、アプリを開いている間だけ鳴る。** 他のアプリを見ている間は鳴らない
  （iOS の Web アプリは JavaScript が止まるため）。
  そのため休憩中は画面を点けたままにしている。復帰時には正しい経過時間が表示される
- iCloud 同期・HealthKit 連携・Apple Watch 対応は対象外
